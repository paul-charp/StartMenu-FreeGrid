# StartMenu FreeGrid

Standalone tool (C++/WinRT, no Windhawk) placing pinned apps and folders freely on a grid in the native Windows 11 Start menu. Ported from a Windhawk mod (git history). Brief: vault `🤖 Claude/Handoff/2026-11-18 Handoff Windhawk Start menu free grid.md`.

## Build and run

- `./build.ps1 [-Version x.y.z] [-Installer]` (PowerShell): finds VS through vswhere (Build Tools locally, VS on GitHub runners), `cl`/`rc` directly (no CMake/Ninja), Release x64 into `build\`. C++20, `/MT` (the dll runs inside StartMenuExperienceHost, no VC runtime dependency), `/W3`, UNICODE. `-Version` writes `build\version_override.h`; `-Installer` runs Inno Setup 6 (`installer/StartMenu-FreeGrid.iss`) if ISCC is found, else fails.
- Version: `src/common/version.h` (`STARTGRID_VERSION_TEXT`, numeric parts), also used by the `.rc` VERSIONINFO. Release: bump `version.h` + `CHANGELOG.md`, tag `vX.Y.Z`, push the tag; `.github/workflows/release.yml` checks tag = version.h and publishes the installer only. `ci.yml` builds on push/PR and uploads the installer as artifact.
- Icon: `res/StartGrid.ico`, generated by `tools/make-icon.ps1`.
- `src/dll`: `StartGrid.dll` (the TAP, `StartGrid.cpp`; `host.cpp` = log, settings, cells, settings watcher). Exports `DllGetClassObject` and `DllCanUnloadNow` through `StartGrid.def`.
- `src/exe`: `StartGrid.exe` (GUI subsystem; CLI `enable`, `disable`, `run`, `status`, `reset`, `log`, `version`; no args opens the window: `ui.cpp`, a system XAML island (`DesktopWindowXamlSource`) built in code, theme from `UISettings`, manifest with `maxversiontested 10.0.18362.0` + PerMonitorV2 in `StartGrid.manifest`; single instance via `Local\StartGrid.UI`). `src/common/shared.h`: event names, CLSID, data dir, log writer.
- Data dir `%LOCALAPPDATA%\StartGrid\`: `cells.txt`, `settings.ini`, `log.txt` (both sides append, truncated over 1 MB), `bin\<timestamp>\` installed copies (a running Start keeps the old dll locked: never overwrite, always a new folder).
- Events: `Local\StartGrid.Disable` (manual reset, dll restores the stock layout), `Local\StartGrid.Stop` (watcher exits), `Local\StartGrid.Reset` (auto-reset, created by the dll; clears all cells). Mutex `Local\StartGrid.Active` = a dll copy is active (only one at a time). Mutex `Local\StartGrid.Watcher` = one watcher.
- Attaching: the exe (`run`) calls `InitializeXamlDiagnosticsEx` itself on each `StartMenuExperienceHost.exe` pid. XAML then loads the dll in Start and calls `DllGetClassObject` > `Tap::SetSite`. The dll pins itself and stays loaded in Start until Start restarts; disable only restores the layout, and a later `SetSite` re-activates it.
- XAML diagnostics: call `InitializeXamlDiagnosticsEx` with `VisualDiagConnection1..N` until it stops returning `ERROR_NOT_FOUND` (0x80070490), with `L""` as the diagnostics dll. Advise the visual tree from a separate thread, never from `SetSite`.
- `#undef GetCurrentTime` before the winrt XAML headers.
- `GetTempPath` inside `StartMenuExperienceHost.exe` is the user `%TEMP%`, not the package `AC\Temp`.
- Installer: per-user in `%LOCALAPPDATA%\Programs\StartMenu-FreeGrid`; runs `enable` after install and `disable` on uninstall. The watcher runs from `%LOCALAPPDATA%\StartGrid\bin`, not the install dir.
- Don't run `enable`/`disable`/`run` from automation: they touch the live Start menu.

## Start XAML (26H2 build 26300.9974, new Start)

Dumped with a throwaway visual tree dump TAP (in git history).

Start uses system XAML (`Windows.UI.Xaml`) plus WinUI 2 (`Microsoft.UI.Xaml.CBS`).

Path to the pinned grid:
```
Window #Start > … > StartMenu.StartHome > Grid #PageRoot > SemanticZoom #TopLevelRoot > … >
GridView #AllAppsGrid (header: ContentControl > Grid #TopLevelHeader) >
StartMenu.PinnedList #StartMenuPinnedList > Grid #Root > GridView #PinnedList
```
- Pinned is the header of the All apps grid; both scroll together.
- `#PinnedList`: plain `GridView`, `ItemsPanel` = `ItemsWrapGrid`, `ItemsSource` = `IObservableVector<StartMenu.IPinnedListItemViewModel>`, items `StartMenu.PinnedListTileViewModel`. `CanReorderItems`, `CanDragItems`, `AllowDrop` all on.
- Containers: `GridViewItem` 96x84 > … > `StartMenu.PinnedListTile` > `Grid #Root` (`#FolderHintPlate`, `#LogoContainer` > `#Logo`, `#DisplayName`).
- Item ID: the `GridViewItem`'s `AutomationProperties.AutomationId` is `tile-` + AUMID (`P~<PackageFamily>!<App>` for packaged apps, `W~<AUMID or known-folder path>` for desktop apps). `AutomationProperties.Name` is the display name. The view model is internal (no `ICustomPropertyProvider`).
- Start sets a fixed local `Height` (rows × 84) on both `#PinnedList` and `StartMenu.PinnedList`. Extra rows clip unless the tool overrides both.
- Swapping `#PinnedList.ItemsPanel` for another panel crashes Start's own code (`StartMenu.dll`, access violation) on folder creation. Keep the native `ItemsWrapGrid` and move tiles with `RenderTransform` from their `LayoutInformation.GetLayoutSlot`.
- Start's drop logic (reorder, add to folder, folder from tile-on-tile) targets the untransformed layout, so it can't be used with moved tiles. The tool handles drags inside the grid with `CanReorderItems` off; folders are managed from the context menu. `CanReorderItems` can't be changed inside `DragItemsStarting` (the drag never starts, and the grid can stay stuck until Start restarts) and Start resets it during a drag.
- Folders have an empty AutomationId and a name that follows their content ("Folder with 2 items including …").
- An open folder (`StartMenu.FolderModal`) covers the grid: drops from it land on the overlay, so listen on the XAML root with `handledEventsToo`.
- Folders open in `StartMenu.FolderModal #StartFolderModal`.
